# SpeedReader Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android APK of SpeedReader (touch-only reader, fixed 200 wpm, same library) built by GitHub Actions and attached to every `v*` release.

**Architecture:** The existing `speedreader` package (model, store, loveread source, `TickerView`) is reused untouched. A new module `speedreader/mobile.py` holds the three phone pages and `MobileWindow`; `packaging/android/main.py` is the entry point. `packaging/build_android.py` drives `pyside6-android-deploy` + buildozer with pure, tested text-transform functions; a new `build-android` CI job produces the APK.

**Tech Stack:** Python 3.12, PySide6 6.12.0 (official Android wheels, cp310-abi3), pyside6-android-deploy, buildozer 1.6.0, python-for-android (Qt bootstrap), GitHub Actions ubuntu-24.04, unittest with `QT_QPA_PLATFORM=offscreen`.

**Spec:** `docs/superpowers/specs/2026-11-01-android-design.md`

## Review Focus

1. Swipe gesture mid-playback: a right swipe while playing must restart the timer from the new position without a double tick (Task 6 test `test_swipe_right_while_playing_keeps_playing`).
2. Long press that turns into a scroll: moving >20 px must cancel the menu (Task 4 test `test_long_press_cancelled_by_move`).
3. Book removed while the reader page still holds its key: `Key_Back` must not raise (ReaderPage.save_position already checks `store.find`; Task 7 test `test_back_after_book_removed_does_not_raise`).
4. Empty book (zero words) opened on the phone: tap must not start a timer or raise (Task 6 test `test_tap_on_empty_book_does_nothing`).
5. `buildozer.spec` whose `requirements` already contains `certifi` or whose `app` section lacks `version.regex`: the spec editor must not duplicate or fail (Task 9 tests `test_requirements_not_duplicated`, `test_missing_version_keys_ok`).

### Task 4: Long press menu on the mobile library

**Files:**
- Modify: `speedreader/mobile.py`

**Interfaces:**
- Produces: `class LongPressFilter(QObject)` installed on `list.viewport()`, or press/move/release handling in a `QListWidget` subclass `TouchList`; implementer's choice. Contract: `QTimer(singleShot, LONG_PRESS_MS)` started on left press at `pos`; cancelled on release or when `(event.pos() - press_pos).manhattanLength() > DRAG_CANCEL_PX`; on timeout calls `MobileLibraryPage.show_menu(item, global_pos)`.
- `MobileLibraryPage.show_menu(item, global_pos)` builds `QMenu(self)` with actions in this order: «Начать заново» (only if available), «Скачать заново» (only if `detect(entry["source_url"]) is not None`), «Удалить» (always); runs `menu.exec(global_pos)`. For testability, `MobileLibraryPage.menu_actions(key) -> list[str]` returns the action texts, and `MobileLibraryPage.run_action(key, text)` performs it; `show_menu` uses both.
- Actions: «Начать заново» → `store.reset_position(key)` then `open_requested.emit(key, True)`; «Скачать заново» → `redownload_requested.emit(key)`; «Удалить» → `QMessageBox.question(self, "Удаление", "Удалить книгу?")`, on `Yes` `store.remove(key)` then `refresh()`. `LibraryError` → `_warn`.
- `MobileLibraryPage.long_press_timer: QTimer` exposed for tests.
- The timer's `timeout` must reach `show_menu` through a lambda (`lambda: self.show_menu(...)`), not a bound method captured at init: the test patches `show_menu` on the instance.
